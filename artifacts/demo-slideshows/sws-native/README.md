# P07 — SeedWater native Moxi replay

Thirteen genuine AppKit `cacheDisplay` captures from the external application
`/Users/davmash/code/moxi-sws`, using the existing slideshow manifest v1/render
schema. Each is labeled **offscreen-render**, not compositor or physical-input
evidence. Generated PNGs and `index.html` are ignored. Shared gallery and planning
files are untouched.

The sequence covers asymmetric overlay, frame/contrast/zoom and native pan,
seed placement/movement plus polygon watershed, semantic undo/redo, atomic
save/reopen, delayed/stale/failed/cancelled computation, explicit corrupt-file
recovery, resize, two-owner isolation and disposal/recreation. AppKit pointer
callbacks are injected into the real view; pixels are generated by Moxi native
composition/controls, not mocked. Selected cell measurements and contour are
linked to actual labels. 168 captured pixel centers are checked against the
scientific raster at multiple zooms, with the PNG's embedded display profile
converted to sRGB only for comparison; original captures remain unchanged.

## Exact reproduction

Prepare dependencies and the pinned reference as described in the application
README. Use the same isolated Moxi tree (base `bd3cccd`, preserving D04) and
matching compiler. This command records source hashes before compilation, runs
headless/scientific/native checks, and fails if any source changes after replay:

```sh
cd /Users/davmash/code/moxi-sws
export MOXI_ROOT=/Users/davmash/.t3/worktrees/moxi/t3-983abb96
export MOJO=/Users/davmash/code/moxi/.pixi/envs/default/bin/mojo
export MODULAR_HOME=/Users/davmash/code/moxi/.pixi/envs/default/share/max
export SWS_REFERENCE=/tmp/moxi-p07-reference
export SWS_LEGACY_PYTHON=/tmp/moxi-p07-legacy-env/bin/python
PYTHONPATH=. .venv/bin/python scripts/evidence.py
```

`source-hashes.json` contains every nonignored application file and every tracked
or nonignored Moxi file outside generated artifact trees, including direct and
transitive code, tests, scripts and build configuration. `build.json` records
counts, source-manifest hash, after-replay equality, full toolchain and binary
hashes. The source-free consumer builds from precompiled `moxi.mojoc`,
`moxi_canvas.mojoc` and native `window.o`, without Moxi source import paths or
implementation includes. The Python app dynamically loads the resulting library.
This is not a published package/installer claim.

`science.json` records eighteen independent pinned-reference cases and both
partition/identity equality, including flat-intensity ties. The fixture itself
was generated by the exact original method with NumPy 1.22.0 / mahotas 1.4.11.
`metrics.json` retains 60 frame samples and eight process-request samples, upload
bytes, host/backend/stack dimensions and peak RSS scope. Frame intervals end at
Moxi's synchronous AppKit flush, before compositor/scanout. Warm pan reuses the
image without uploads; each scientific/display raster publication copies 58,404
RGBA bytes for a 157×93 frame. This tiny synthetic workload does not establish
large-stack or sustained performance. Process startup is deliberately included
in request latency and excluded from kernel timing.

Logs: `/tmp/moxi-p07-native-build.log`, `-contracts.log`, `-science.log`,

these are not treated as scientific evidence. `manifest.json` includes every
capture's dimensions and SHA-256. Reuse `scripts/demo_slideshows.py` to validate or
render this single manifest; do not regenerate the shared master gallery.

## Explicit acceptance gates

Physical editing, human scientific acceptance, IME, VoiceOver (paused), external
stacks/legacy imports, Linux/Windows, real power-loss durability, sustained
performance and production packaging remain unverified. The full Moxi suite and
D04 suite were not run for this narrow native image change; focused owner/sampling
regressions and application replay are separate evidence. No hardware control,
network service, private data, commit, remote, PR or publication is included.
